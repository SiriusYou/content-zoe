# Healthcare AI Needs a Carry-Forward File

Healthcare AI governance should not reset at the calendar boundary. This report makes a governance-continuity argument, not a factual survey of any local year-end review program.

The staged source pack supports a practical question: how does unfinished AI governance work remain visible when one review cycle ends and the next begins?

The answer proposed here is straightforward. A carry-forward file can keep unresolved work reviewable instead of letting it disappear into a new calendar, a new packet, or a new reporting cycle.

That visibility matters because healthcare AI work rarely ends cleanly on December 31. Approvals may still carry conditions. Monitoring evidence may exist but remain unread. Validation triggers may have fired without a completed local review. Workflow changes may have created new governance work that no one has formally closed.

The year boundary is therefore a governance hazard. It can create the false impression that a new cycle starts with a clean slate even when the underlying questions remain open.

## The File Is Not the Inventory

A carry-forward file is not the local inventory or register. The inventory states which AI-enabled workflows exist. The carry-forward file states which of those workflows still have open governance work attached to them.

That distinction matters. An inventory can show that a workflow is active, paused, narrowed, retired, replaced, or under review. A carry-forward file explains why that status still needs attention and what must happen next.

Used well, the file becomes a continuity surface. It links unfinished items back to the workflow record when one exists while preserving the details that should not be lost during handoff.

## What Should Carry Forward

The goal is not to create a second master list. The goal is to preserve continuity for open items.

Useful carry-forward categories include:

- workflows still awaiting review;
- approved uses with unresolved conditions;
- monitoring evidence not yet reviewed;
- unresolved validation triggers;
- incomplete source attributes or implementation details;
- recent unreconciled changes;
- owner confirmation still pending;
- near misses, incidents, or user concerns that should inform the next review;
- fallback paths that are not yet tested or documented;
- retirement, replacement, narrowing, or pause questions that remain open.

Useful fields can include workflow, owner, current status, last review, next review trigger, open decision, evidence gap, monitoring gap, recent change, near-miss or incident link, fallback status, retirement state, and escalation path when those records exist.

Unknowns should remain visible as unknowns. They should not be silently converted into assumed approval, assumed validation, assumed monitoring coverage, or assumed owner confirmation.

## Reconcile It Against the Workflow Map

The carry-forward file works best when it is reconciled against the local inventory or register. Every open item should link back to a workflow entry when one exists. Every active or recently changed workflow should be checked for unresolved evidence, ownership, monitoring, fallback, change, or retirement questions.

That reconciliation should look beyond standalone tools. Healthcare AI can be embedded, indirect, or easy to overlook. Open items may sit inside EHR modules, documentation support, imaging support, triage, referral routing, scheduling, billing, coding, prior authorization support, analytics, quality reporting, or operations queues.

This is why the handoff cannot rely on a narrow tool list alone. A workflow may look routine on the surface while still carrying unresolved AI-related review work underneath it.

## Monitoring History and Change Debt Belong in the Handoff

The next review cycle should not start without the monitoring and change context that shaped the last one. If monitoring notes, source updates, user concerns, near misses, incidents, or workflow changes exist, they should remain connected to the affected workflow in the carry-forward file.

This is also where change debt belongs. Change debt is review work created by change but not yet closed. It can appear after a vendor update, a model-behavior shift, a workflow expansion, a new downstream action, an unclear escalation path, or a pending training or documentation update.

The handoff does not need to prove that those changes caused harm. It only needs to prevent the next cycle from forgetting that the review work still exists.

## Owner Follow-Up and Expiring Decisions

A carry-forward file should also make clear who needs to act next. That does not mean inventing a local committee map. It means preserving owner follow-up as an explicit governance question.

Year-end review is a useful moment to ask whether the owner still exists, still accepts responsibility, and still has a route to escalate concerns. It is also a useful moment to reopen decisions that should not silently continue, such as conditional approvals, deferred validation, temporary change acceptance, untested fallback plans, or pending owner transitions.

Possible next actions may include continue, narrow, pause, retire, replace, reopen review, request evidence, validate locally, update training, update monitoring, or escalate for decision. These are action categories, not universal prescriptions.

## Retirement Still Needs Visibility

Retired, replaced, narrowed, or paused workflows may still belong in the carry-forward file when dependencies remain open. Stored output, staff communication, training reversal, fallback readiness, vendor transition, unresolved review threads, or archive questions can all survive the end of active use.

Retire or archive is therefore not the same as disappear. If governance-relevant questions remain open, the next cycle still needs a record of them.
