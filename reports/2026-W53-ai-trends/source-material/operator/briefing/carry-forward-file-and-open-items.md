# Carry-forward file and open items

## Core idea

The year boundary creates a common governance hazard: work that was visible inside one review cycle can become harder to see when the next cycle starts. Healthcare AI oversight should not treat the calendar reset as a governance reset. A carry-forward file makes open AI governance work reviewable across that boundary.

The carry-forward file is not the full AI inventory. It is a continuation surface connected to the inventory or register. The inventory says what exists. The carry-forward file says what still needs attention.

## Useful open-item categories

The source-bounded report may describe open items such as:

- workflow still awaiting review;
- approved use with conditions that have not been closed;
- monitoring evidence not yet reviewed;
- validation trigger that has not been resolved;
- owner confirmation still pending;
- source attributes or implementation details still incomplete;
- recent change that has not been reconciled;
- near miss, incident, or user concern that should inform next review;
- fallback path not yet tested or documented;
- retirement, replacement, narrowing, or pause decision still open.

## Operating function

The file should help a governance group ask what must carry forward, not simply what happened. It can reduce ambiguity by naming owner, next action, review trigger, due date or review window when one exists, and the reason an item remains open.

Keep unknowns visible. If a field is unknown, mark it as unknown rather than assuming continued approval, local validation, owner confirmation, or monitoring coverage.

## Boundaries

Do not claim that a carry-forward file proves safety or compliance. It is a visibility tool and a continuity artifact. It helps a team avoid losing the thread; it does not decide the merits of any workflow by itself.
