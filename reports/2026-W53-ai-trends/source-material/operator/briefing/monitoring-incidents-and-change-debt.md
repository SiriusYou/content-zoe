# Monitoring, incidents, and change debt

## Why monitoring history belongs in the handoff

AI governance continuity depends on remembering what changed and what was observed. A carry-forward file should not only list open reviews; it should also connect relevant monitoring signals, user feedback, incidents, near misses, and change records to the workflows they affect.

The staged sources support monitoring, measurement, change management, source attributes, system management, contingency planning, and lifecycle review as governance concerns. They do not provide local monitoring data or incident counts.

## Change debt

Change debt means review work created by a change but not yet closed. Examples include:

- vendor update or model behavior change not yet reviewed locally;
- source-attribute update not reflected in local records;
- workflow change that expands users, setting, output, or downstream action;
- monitoring threshold or escalation path still unclear;
- training, user notice, or documentation update still pending;
- rollback, fallback, or contingency procedure not yet reconciled.

The report should use the phrase as an operating concept, not as a formal legal or accounting category.

## Near misses and incidents

Near misses and incidents can create carry-forward obligations for learning and review. The report may say the file should link relevant threads to the affected workflow when those records exist.

Do not invent incidents or near misses. Do not claim that a missing carry-forward file caused harm. The source-bounded point is that review continuity is weaker when these threads are disconnected from the next review cycle.

## Boundaries

Monitoring notes, change records, and incident links can make review more visible. They do not prove safety, compliance, harm reduction, patient trust, or maturity.
