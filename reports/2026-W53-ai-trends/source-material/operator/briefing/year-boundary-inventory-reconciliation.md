# Year-boundary inventory reconciliation

## Link to W52 inventory frame

The W53 report should build naturally from the prior local-inventory argument without repeating it. The local inventory or register is the base map. The carry-forward file is the year-boundary handoff that says which parts of the map still need action.

If a workflow is active in the inventory but has unresolved evidence, ownership, monitoring, change, fallback, or retirement questions, those questions should not disappear at the calendar boundary. They should carry forward as named review items.

## Reconciliation questions

The report may recommend reconciling the carry-forward file against the local inventory:

- Does every open carry-forward item link to a workflow or register entry?
- Does every active, paused, narrowed, replaced, retired, or pending-review status still make sense?
- Did any workflow change owner, setting, users, approved use, data source, model behavior, output type, or downstream workflow?
- Did any item acquire a new incident, near miss, complaint, monitoring signal, source-attribute update, validation trigger, or fallback concern?
- Are retired or replaced items still visible where they leave dependencies, data, contracts, user training, patient communication, or fallback questions?

## Embedded and indirect use

Reconciliation should not cover only standalone AI tools. Embedded or indirect AI-enabled functions may sit inside EHR modules, documentation workflows, imaging support, patient portals, triage, referral routing, scheduling, billing, coding, prior authorization support, analytics, quality reporting, and operations queues.

The staged sources support looking broadly at workflows. They do not support claiming that any named organization has found all embedded AI use.

## Boundaries

Do not imply that an inventory export or spreadsheet is sufficient proof of governance. Reconciliation can improve visibility, but it does not prove completeness, safety, compliance, fairness, or operational maturity.
