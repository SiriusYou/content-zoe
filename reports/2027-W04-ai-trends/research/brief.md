# Research Brief

## Scope

- Job: `2027-W04-ai-trends`
- Topic: `AI in healthcare - weekly`
- Locales: `en`, `zh`
- Source posture: use only the staged local source basis; do not add external facts, named implementations, or measured outcomes.

## Core thesis

Healthcare AI governance needs a visible disagreement path. An AI-enabled output can be wrong, incomplete, misfit to the setting, difficult to act on, or outside a user's professional judgment. If the workflow does not show how a user can question the output, document a concern, use an alternate path, escalate the issue, or trigger review, then the organization may have an output without a practical way to challenge it.

## Implementation direction

- Prefer the title `Healthcare AI Needs a Disagreement Path` unless drafting yields a stronger source-bounded variant.
- Keep the article centered on contestability, user action, escalation, and review routing.
- Frame the disagreement path as a governance and workflow discipline, not as proof of safety, compliance, effectiveness, fairness, trust, resilience, or maturity.
- Use public-facing phrasing such as `the source basis`, `available governance sources`, `disagreement path`, `challenge route`, `alternate action`, `escalation route`, `review trigger`, and `use boundary`.

## Recommended article structure

1. H1 with no calendar key.
2. `EVIDENCE_GRADE_WARN` comment in the matching locale only.
3. Short lede explaining why a model-enabled output should not be the last word.
4. Section on why a visible challenge route matters in real workflow use.
5. Section on what makes a disagreement path operationally useful.
6. Section on alternate actions, escalation, and review triggers.
7. Section on unknown, unusable, and disputed routes staying visible.
8. Brief evidence-limits section.
9. `Selected Source Basis` using only public source-family names.

## Operational elements to cover

- intended users
- output use
- challenge route
- alternate action or non-AI path
- documentation location
- escalation contact
- review trigger
- monitoring responsibility
- owner group
- unresolved evidence gaps

State these as useful fields when they exist. Do not imply every local workflow contains all of them.

## Safe claims

- A disagreement path can make concerns easier to route by showing how users can question an output, document a concern, use an alternate path, escalate unresolved issues, and trigger review when appropriate.
- The path should connect to actual workflow use, not only to a model name, vendor name, or dashboard field.
- Repeated disagreement, workaround patterns, missing context, disputed use boundaries, unclear ownership, or unreviewed monitoring signals can justify review.
- Unknown or unusable routes should remain visible rather than being treated as resolved.
- Available governance sources can support disciplined questions about contestability, documentation, escalation, monitoring, and responsible adoption.

## Red lines

- Do not claim any named vendor, hospital, health system, regulator, or public program has or lacks a sufficient disagreement path.
- Do not claim a disagreement path satisfies legal, regulatory, accreditation, certification, privacy, procurement, or liability duties.
- Do not claim a disagreement path proves safety, compliance, effectiveness, fairness, trust, outcome improvement, resilience, continuity, or maturity.
- Do not invent dispute logs, override rates, committee names, owner rosters, audit trails, incidents, validation results, or implementation proof.
- Do not present FDA device context as the whole healthcare AI landscape.

## Evidence limits to keep explicit

- The source basis supports a cautious governance article, not local implementation proof.
- The available governance sources do not provide local dispute logs, override rates, committee charters, audit logs, legal analysis, measured outcomes, or named implementation proof.
- Monitoring language must stay conditional. Mention concern counts, overrides, or feedback only as possible signals when such data exist; do not invent measurements.
