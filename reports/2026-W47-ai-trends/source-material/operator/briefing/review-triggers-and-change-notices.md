# Review triggers and change notices

## Editorial use

Use this file to make scope control operational. The report should identify events that should trigger review before AI use expands or continues under a new assumption.

## Source basis

- NIST AI RMF supports monitoring, governance, roles, and responses across the AI lifecycle.
- FDA software and CDS materials support function-specific context and intended-use discipline.
- ONC DSI materials support source-attribute visibility in covered decision-support contexts.
- Joint Commission/CHAI responsible-use guidance announcement supports local validation and monitoring adapted to context.

## Reader-safe claims

- Review triggers can include a new user group, new setting, new patient population, new data source, new interface, new vendor release, new model behavior, new downstream action, or new reliance pattern.
- Change notices should reach the people who own review, training, monitoring, fallback, and escalation.
- Expansion review should decide whether the approved use is unchanged, narrowed, paused, or reopened for validation.
- Monitoring should compare actual use against the approved-use record, not only model output quality.

## Claims to avoid

- Do not claim change notices prove users understood the change.
- Do not claim monitoring prevents use creep.
- Do not claim every change requires the same review level.
- Do not imply source attributes or model documentation alone are enough for expansion approval.

## Evidence limit

The staged sources support trigger and notice questions. They do not include local change logs, notification records, user comprehension evidence, or monitoring results.
