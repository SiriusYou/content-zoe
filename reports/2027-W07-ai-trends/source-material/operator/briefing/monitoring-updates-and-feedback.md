# Monitoring, updates, and feedback

## Why uncertainty changes over time

An output's uncertainty can change when the workflow changes, the source data changes, users adapt around the output, performance is reviewed, a fallback route fails, or a downstream action becomes more consequential. The article may say that uncertainty labels should not be frozen if the surrounding workflow changes.

This is not a claim that every output needs real-time monitoring. It is a source-bounded argument that uncertainty communication should remain connected to review, feedback, and update practices.

## Feedback that can inform review

- user confusion;
- repeated override;
- non-use;
- unexpected reliance;
- missing context reports;
- fallback use;
- escalation frequency;
- documentation gaps;
- disagreement about output meaning;
- changed workflow conditions.

These signals can help decide whether the label, workflow, review trigger, or fallback route needs attention. They do not prove safety, compliance, effectiveness, fairness, or outcome improvement.
