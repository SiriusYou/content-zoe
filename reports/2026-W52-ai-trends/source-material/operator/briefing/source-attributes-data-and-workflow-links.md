# Source attributes, data, and workflow links

## Editorial use

Use this file to connect the inventory with evidence and data visibility. The report should argue that an inventory is stronger when each listed workflow links to source attributes, data dependencies, decision-support role, and local workflow context.

## Source basis

- ONC DSI material supports attention to source attributes, evidence, logic, references, implementation information, and transparency in decision support.
- NIST AI RMF supports context mapping, documentation, measurement, monitoring, and lifecycle risk management.
- FDA AI/ML-enabled medical devices material can be used only as bounded device-context evidence that public lists can identify some AI-enabled device functions. It does not define all healthcare AI.

## Reader-safe claims

- Inventory entries should link to source attributes and evidence where available.
- Useful fields can include data source, update cadence, integration point, output type, human action expected, downstream workflow, monitoring signal, and fallback path.
- The inventory should distinguish vendor evidence from local evidence and should not let source attributes substitute for local review.
- Some items may have device-regulatory context; others may be administrative, operational, documentation, or communication workflows outside that device frame.
- Missing evidence should be visible as an inventory field rather than hidden.

## Claims to avoid

- Do not claim source attributes prove transparency, safety, fairness, compliance, or trust.
- Do not claim FDA-listed device context covers all healthcare AI.
- Do not invent data sources, model cards, device status, or source attributes.
- Do not use the inventory to rank vendors or products.

## Evidence limit

The staged sources support data/source-attribute linkage questions. They do not include local model cards, device determinations, training data, source attribute records, or validation evidence.
