# Unknown, stale, and missing context

## Unknown context

Unknown handoff context should remain visible. If the receiving user cannot tell what use boundary was reviewed, who owns follow-up, what evidence gaps remain, or where concerns go, the output is not fully contextualized. The next action may be owner confirmation, boundary clarification, evidence review, or escalation.

The article should frame unknown context as a governance routing problem, not as proof that the workflow is unsafe or noncompliant.

## Stale context

Context can become stale when users change, settings change, evidence changes, output purpose changes, monitoring signals change, or ownership changes. The source-bounded claim is not that any specific context is stale. The claim is that handoff context needs enough recency and ownership information to make stale context visible.

## Missing context

Missing context should not be silently filled in by the receiving user. If the handoff note lacks use boundary, intended receiver, evidence limits, fallback contact, or escalation route, the gap should remain visible rather than being converted into assumed approval.

The article may connect this point to review-date and disagreement-path thinking from prior themes, but it should keep the primary focus on handoff context.
