## A. Re-instated locked decisions (HIGH severity — missing from current revision)

### A1. Crash recovery via `stage_started_at` (was Issue 1A)

**Add to `jobs` table:**

```sql
stage_started_at INTEGER  -- unix ms when current_stage entered
```

**Add to `bin/report.ts` startup logic:** before processing a job, scan for jobs in `status=running`. For each such job, treat the prior `current_stage` as failed-partial: roll the job back one stage, increment `attempt_id`, set `status=queued`, write a `stage_rolled_back` event with `{from_stage, started_at, detected_at}` payload. Then proceed.

**Why:** the split-process model didn't eliminate the failure mode. A `bun run report` that's killed mid-research (laptop sleep, ctrl-C, OOM) leaves a row in `running` with no live process. Without the rollback, the next invocation either no-ops (if it filters by status) or double-runs (if it doesn't).

### A2. Subprocess lifecycle pattern (was Issue 1B)

**Specify in `src/llm/codex-cli.ts` design:** mirror the upstream pattern at `openclaw-healthcare/src/lib/agents/codex-adapter.ts:316–336` and `:415–422` *including*:

- `spawn(... { detached: true, stdio: ["ignore", "pipe", "pipe"] })`
- `child.unref()` after spawn
- `process.kill(-child.pid, "SIGTERM")` for cancellation (note the negative PID — kills the entire process group, not just the immediate child; required because Codex `--full-auto` forks web-search workers)
- The `LLMProvider` interface MUST expose a `kill(): void` method so stage handlers can cancel on timeout (A3) and the bot can cancel on `/reject` of an in-flight job

**Why:** the previous review caught this exact gap. Saying "mirrors openclaw-healthcare pattern" without naming the lifecycle pieces invites the same drop on implementation. The git-commit-on-complete part of the upstream IS optional for content-zoe; the lifecycle part is not.

### A3. Per-stage timeouts (was Issue 1E, now covering 5 stages)

**Hard-coded constants in `pipeline/stages.ts`:**

| Stage | Timeout |
|---|---|
| `research` | 20 min |
| `draft_en` | 15 min |
| `edit_en` | 10 min |
| `translate_zh` | 5 min |
| `awaiting_approval` | none (operator-bound) |

On timeout: stage handler calls `provider.kill()`, marks job `status=failed`, `current_stage=<the stage that timed out>`, writes `error="stage timeout: {stage} exceeded {n}m"`, exits non-zero.

**Why:** Codex `--full-auto` with `model_reasoning_effort="high"` can hang indefinitely on a stuck tool call. Without timeouts, A1's recovery only kicks in if the operator notices and ctrl-Cs the run.

## B. Quality gate restored (HIGH severity — previously locked, missing)

### B1. Evidence Grade pass in `edit_en` (was TODO 3 → "Build into v1")

**`pipeline/edit-en.ts` description, replacement text:**

> Codex spawn with editor prompt. Revises `report.en.md` in place AND appends a final section titled `## Evidence Audit` containing a Markdown table:
>
> | Claim (paraphrased) | Source URL | Quoted snippet (≤ 30 words) | Grade |
> |---|---|---|---|
>
> Grades use the harness_overlay rubric: **A** = primary source with quoted text supporting the claim verbatim. **B** = secondary source with paraphrase support. **C** = no source (model assertion). The editor prompt instructs that any claim with no source must be marked Grade C.
>
> Generates short `approval_summary` (~200 words) for Telegram preview AND a one-line evidence summary (`"Evidence: 12 claims | A:7 B:4 C:1"`). If C-count > 0, summary is prepended with `⚠️ N ungrounded claim(s)`.

**Why:** without per-claim grading, "data-backed weekly report" is fiction; approval is vibe-checking. This was explicitly chosen during the prior review as the highest-leverage quality decision and silently disappeared in the revision.

## C. Bilingual reject-path tightening (NEW — accepted during this delta)

### C1. Add `translation_off` to `RejectType`

**`src/types.ts`:**

```typescript
type RejectType =
  | "factual_error"      // claims don't match sources
  | "voice_off"          // brand voice misaligned with SOUL.md
  | "structure_broken"   // sections out of order, missing, or malformed
  | "length_wrong"       // too short / too long for cadence
  | "translation_off"    // Chinese translation tone, accuracy, or terminology issue
  | "other"              // free-form; reject_reason required
```

### C2. Targeted rewind based on `RejectType`

**`pipeline/stages.ts`:**

```typescript
const REJECT_REWIND_TARGET: Record<RejectType, Stage> = {
  factual_error:    "research",      // re-collect sources, rewrite, re-edit, re-translate
  voice_off:        "draft_en",      // re-write, re-edit, re-translate
  structure_broken: "draft_en",      // re-write, re-edit, re-translate
  length_wrong:     "draft_en",      // re-write, re-edit, re-translate
  translation_off:  "translate_zh",  // re-translate only — preserves good en
  other:            "draft_en",      // safe default
}
```

The next stage handler reads `reject_type + reject_reason` from the job row and conditions its prompt on them.

**Why:** without this, every Chinese-only translation issue forces a full English re-write + re-edit + re-translate (~30+ min wasted). Inverse: every factual reject must re-translate too (correct — facts change → both languages must change).

## E. Open questions surfaced by delta review

1. **Approval granularity:** with bilingual output, do you ever want to approve en + reject zh independently? Plan currently couples them. If yes, the bot needs `/approve-partial` or two separate approval messages. If no (current behavior), the targeted rewind in C2 is sufficient.
2. **`translate_zh` cost:** adds another full Codex call (~5–10 min, ~thousands of tokens). Acceptable for v1, but it is the thing most likely to push you toward a smaller/cheaper model for that one stage. Note: `-m gpt-5.4` is locked for ALL stages currently.
3. **Bundle promotion when `translate_zh` partially fails:** if zh stage produces a file but it's noticeably bad (length 0, control chars, etc.), should the contract validator (item D, "Codex contract validation") promote the bundle anyway with a warning, or hard-fail? Recommend hard-fail — operator can re-run translate_zh via /reject `translation_off`.
